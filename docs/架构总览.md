# Windroid 架构总览

Windroid 让用户在自己的电脑上运行 Android 应用，每个应用以独立原生窗口出现。应用库是入口。设备窗口展示所选实例的主屏，每个应用窗口展示为该包分配的 Android 虚拟显示。当前发布目标为 Apple 芯片的 Mac，构建与首次启动方式见[使用说明](../README.md)。

本文只回答三件事：系统切成哪几块、块之间的依赖方向、哪些约束不容违反。各域的内部设计不在本文展开。

**证据标注**：全文使用三种标记。**[实测]** 有可直接复现的观察支撑，详见 [实测/01-运行环境域](./实测/01-运行环境域.md)；**[规范]** 来自外部规范或第三方源码（scrcpy、Android、adb）；**[推断]** 是本设计基于前两者的判断，尚未实测。

## 1. 从需求推导切分

需求里存在三种性质完全不同的失败。它们不共享故障原因，也不该共享恢复路径：

1. 运行时组件缺失、镜像损坏、端口被占、进程没起来 —— 环境问题；
2. 对同一台 Android 实例的并发状态变更相互覆盖 —— 一致性问题；
3. 解码卡顿、输入时序错乱、窗口关不掉 —— 呈现问题。

应用库协调实例操作和显示会话。两条路径按各自观察到的结果更新窗口。

```text
应用库与窗口管理
  ├─ 实例和包操作 → 每实例一个设备 actor → 运行时后端 → 模拟器和 adb
  └─ 显示和输入   → 每显示一个流会话 → 独立的视频和控制通道
```

运行环境域提供托管组件、实例身份和数据盘。设备 actor 串行处理实例命令并发布快照。宿主根据快照判断是否允许开窗，再将该实例的 serial、adb、server 路径和显示目标交给流会话。帧与输入始终绑定所属窗口，Android 任务读数用来确认包与显示的对应关系。

## 2. 各域职责与对外形态

| 域 | 负责 | 不负责 | 对外形态 |
|---|---|---|---|
| 运行环境域 | emulator / adb / scrcpy-server 组件、系统镜像、实例存储、端口分配、进程启停 | 应用语义、窗口、解码 | 实例的创建、启动、停止，以及实例的地址与组件版本 |
| 设备域 | 一台 Android 实例的状态快照与实例、包操作 | 解码、UI、跨实例协调 | 命令、事件、只读快照 |
| 流域 | 一个窗口的视频解码、帧输出、输入注入时序 | 窗口所有权、应用语义 | 帧流与输入通道 |
| 呈现域 | 前端：用户看到的目录与设置；表面：窗口所有权、视频表面、输入捕获和坐标换算 | 协议、设备状态 | 平台原生的窗口与视图 |

**设备域的接口形态是硬约束，不是风格选择**：

- **命令（command）**：请求一次状态变更，有明确的结束与明确的失败原因；
- **事件（event）**携带递增序号，通知宿主读取最新快照。
- **只读快照（snapshot）**：任意时刻可整体取出的事实集合；调用方据此渲染，而不是自己累积状态。

由此推出两条实现约束：**[推断]**

1. 设备域**不得假设与调用者同进程**。接口参数与返回值必须可序列化，不得包含共享可变引用、闭包、平台对象（窗口句柄、文件描述符）。
2. 实例状态由设备 actor 根据事实派生。宿主组合设备快照、Android 任务和本机窗口记录，供应用库渲染。

这样将来把设备域抽成独立守护进程时，只换传输层，调用方不动。

## 3. 形态 A：单进程

应用库、窗口管理器、设备 actor 和每路解码线程位于同一个 macOS 主机进程。模拟器与 adb 使用各自的子进程。设备 actor 顺序处理发给该实例的命令，发布供应用库读取的快照。

当前四个域共用宿主进程。第 2 节的可序列化契约允许今后将设备 actor 独立部署，届时需验证进程间通信、生命周期与故障恢复。

为在宿主意外退出后仍能收集正在运行的模拟器输出，日志设计为每次模拟器启动配一个采集子进程，其生命周期限于本次输出。实例及其停止权仍归宿主。交互原型和原生实施边界见[诊断日志](./架构/诊断日志.md)。

## 4. 多实例是一等公民

宿主通过实例注册表绑定每次操作的目标。多实例运行时使用以下身份与存储规则。

| 对象 | 归属或约束 |
|---|---|
| 应用与窗口 | 由实例标识和包名共同定位。设备窗口绑定实例主屏。 |
| 端口 | 分配器预留端口并记录所属实例。 |
| 系统镜像 | 同一只读镜像可供多个实例使用。 |
| 实例数据 | 每个实例独立保存用户数据和快照。 |
| 停止操作 | 释放所选实例及其窗口占用的资源。 |

实例内的应用状态、窗口和缓存都须携带实例身份。运行组件、系统镜像目录和应用窗口的默认关闭策略归宿主管理。

## 5. scrcpy 的不对称性

scrcpy 由两半组成，两半的架构待遇完全不同：**[规范]**

- **server**：设备端的 Java jar，第三方固定产物。我们只做三件事——下载、固定版本、推送。不为它做架构。
- **client**：主机端的协议实现、解码、渲染、输入回传与窗口。**这部分由我们自研**，本项目全部技术难度集中在这里。

流域实现协议、解码和设备输入注入。呈现域显示视频并捕获用户输入。

## 6. 技术栈与验证门禁

Rust 为核心。UI 层已选定 **nsh（Native Shell）**：它从架构上满足两个否决项——窗口由调用方持有（`AppView` 是 `NSView`），原生组件可承载任意 `NSView` 作为视频表面。两项验证已通过，见 [实测/04-呈现域](./实测/04-呈现域.md)。

nsh 发布不久，属于**需持续观察的选择**：锁定 `0.5.x`、升级单独评估、保留 fork 可能。

若 Rust 的学习与推进成本不可接受，Go 是备选。备选的意思是核心语言可换，而第 1 节的依赖顺序与第 2 节的接口形态不随语言改变。**[推断]**

## 7. 必须满足的约束

以下每条都是硬要求。违反任一条的设计不予合入。

1. **单一写者**：状态必须从事实派生，不允许有多个写者各自赋值同一状态字段；一个状态字段只能有一个写入点。
2. **关窗遵循用户选择**。用户可以选择保留后台、完全退出或取消，并决定是否记住对应用窗口的选择。设备窗口关闭后实例继续运行。
3. **应用入口**：应用库展示 Android 声明了 MAIN / LAUNCHER 的应用，默认桌面的候选由 HOME 单独查询。[应用清单](./架构/02-设备域.md#五应用清单)
4. **应用来源**：依据该实例中 Android 的包来源展示「已安装」和「系统应用」。批量启停针对实例列表中的所选实例。
5. **窗口所有权归我们**：这是实现关闭前拦截的唯一前提。依赖第三方进程拥有窗口的方案，在该需求上不可能成立。
6. **adb 的输出不是成功证据**：命令返回成功不等于状态已达成，必须回读实际状态验证。**[实测]**
7. **失败要分类**：区分"预期内的环境变化"（设备未就绪、组件缺失、用户切换了实例）与"真正的错误"。前者不打扰用户，后者才上报。
8. **键必须带实例身份**：见第 4 节。

## 8. 非目标

明确不做。出现即为范围蔓延：

- 插件系统；
- 配置抽象层：不为未知平台预留配置面；
- 跨平台统一图形抽象层：表面按平台原生实现，不做伪统一；
- 通用事件总线：事件走设备域，不做全局广播；
- scrcpy 协议的多版本兼容：固定单一版本。

## 9. 里程碑

里程碑以「用户能亲手用一下什么」为终点，不以「技术可行性被证明」为终点。

| 切片 | 目标 | 用户拿到什么 | 状态 |
|---|---|---|---|
| M0 | 骨架 | 窗口能开、命令往返、事件送达、界面可渲染 | 已完成 |
| M1a | 画面通道 | 真实模拟器画面进入我们自己的窗口 | 已完成 |
| S1 | 运行时准备 | 组件与许可、下载、暂停/继续、校验、创建实例 | 已接入应用库 |
| S2 | 实例管理 | 私有 AVD、实例列表、切换、启停 | 已接入应用库 |
| S3 | 应用库 | 应用清单、安装 APK、按来源查看应用 | 已接入应用库 |
| S4 | 应用窗口 | 设备主屏和应用独立显示、按窗口输入 | 已接入原生窗口 |
| S5 | 关闭语义与运行中 | 保留后台、完全退出、聚焦或重开应用 | 已接入窗口与运行中列表 |

M1a 的历史验证记录了 1920×1080 的真实模拟器画面。当前源码通过 VideoToolbox 在主机进程内解码 H.264。上表的「已接入」描述现有产品入口。双显示回环测试校验了会话隔离和解码像素，在指定模拟器上复验端到端行为的方法见[流域验证范围](./架构/03-流域.md#验证范围)。

形态与交互见 [产品/01-产品形态与交互](./产品/01-产品形态与交互.md)。

- 子文档与本文冲突时，以本文的依赖顺序与第 7 节约束为准，并修正子文档。
- `工作环境/` 与产品设计无关，产品文档不得引用其结论作为设计依据。
