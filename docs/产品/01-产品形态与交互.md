# 产品形态与交互

本文记录桌面端的目标交互。macOS 的操作路径和界面布局可分别在原型与设计稿中查看。[交互原型](../../output/design/Windroid-Prototype.html) · [可编辑设计稿](../../output/design/Windroid-macOS.pen)

## 一、一句话与三个界面

**Windroid 让 Android 应用以独立的原生窗口运行在用户的桌面上。** 当前发布目标是 Apple 芯片的 Mac，后续桌面目标依次为 Linux（含电视场景）和 Windows。[平台路线](../../README.md#平台进度)

| 界面 | 职责 | 出现时机 |
|---|---|---|
| 应用库（主窗口） | 准备共享运行环境，管理实例及其应用 | 常驻，关闭即退出 Windroid |
| 应用窗口 | 显示同一实例中的一个 Android 应用 | 打开应用时 |
| 设备视图 | 显示所选实例的 Android 主屏、桌面和系统弹窗 | 按需打开，独立于应用窗口 |

## 二、应用库的结构

侧栏可折叠。固定的「实例」入口打开「全部实例」，下方按实例显示名称和状态。启动进度在固定高度的行内更新。侧栏底部的「运行环境」和「设置」面向整台主机。

| 入口 | 操作与作用范围 |
|---|---|
| 实例 → 全部实例 | 逐行显示状态、配置的 CPU、内存、主屏分辨率和用户空间。点击名称进入应用面板，点击行内「设置」管理该实例。 |
| 单个实例 → 应用 | 按 Android 包来源展示有 LAUNCHER 入口的应用，用户安装的归入「已安装」，系统包归入「系统应用」。可打开应用或安装 APK。 |
| 单个实例 → 运行中 | 和「应用」共用一个内容区，切换标签查看该实例的 Android 任务。已开窗的应用可聚焦或转入后台，后台任务可恢复窗口。 |
| 单个实例 → 设备视图、管理实例 | 两个入口常驻。实例就绪后可打开主屏。管理页可检查规格、启停实例及调整设置。 |
| 运行环境、设置 | 运行环境管理全机共享的组件和系统镜像。设置管理应用窗口默认行为、存储位置、Windroid 日志，并提供「引导」。 |

应用清单和运行任务分别读取。首次读取显示加载状态，收到成功的空结果后才显示空态。读取失败时保留上次可用内容，并在对应视图说明失败原因。任务数量未知时省略计数。[原生应用库与任务列表](../../app/ui/library.tsx)

**批量启停。** 可对全部实例执行，也可勾选其中几台。确认页列出作用范围、可执行的实例及跳过原因。停止前提示会关闭的窗口。执行时逐台显示结果，部分失败可只重试失败项。查看单个实例设置后返回列表，保留原有选择。

**实例设置。** 设备模板、系统镜像和用户空间在创建时确定。CPU、内存和图形渲染可在模拟器进程停止后调整。管理页区分配置值与本次启动实际分配的容量。Android 媒体音量和默认桌面在实例就绪后可调，只作用于该实例。桌面候选包括仅声明 HOME 的应用，优先显示已核实的应用名称，缺少名称时显示包名。选择后以 Android 回读的默认值更新界面。「更多」提供重新启动、冷启动和模拟器日志。冷启动跳过快照，保留已安装的应用和文件。

### 日志

在「设置 → 应用日志」查看 Windroid 自身的运行记录。在「管理实例 → 更多 → 模拟器日志」查看所选实例的输出。启动失败时，实例面板也提供直达该次启动记录的入口。

按日期查看时，同一天的多次启动分别列出；按启动记录查看时，同一进程跨午夜的输出连续显示，并保留日期分界。原生采集现状和验收条件见[诊断日志设计](../架构/诊断日志.md)。

## 三、应用窗口

每个应用窗口通过专属的 scrcpy 会话创建虚拟显示，并在该显示上启动目标包。设备视图可同时显示主屏。再次打开同一实例中的同一应用时，会聚焦已有窗口。在两个实例打开同一包时，各有独立窗口，输入、恢复与关闭都只作用于对应实例。

「设置 → 应用窗口」配置新窗口的默认方向与高度。同一实例中的应用再次打开时可沿用自己的窗口尺寸。缩放时，Android 重新布局虚拟显示，过渡期间画面按比例居中。设备视图始终按主屏比例显示。[显示与输入契约](../架构/03-流域.md)

macOS 可为新安装的 Android 应用创建启动器，从 Spotlight 或程序坞打开。自动创建是全局偏好，每个启动器绑定到相应实例和应用。

## 四、关闭语义

首次关闭仍在运行的应用窗口时，Windroid 在该窗口标题栏下询问如何处理。窄窗口的确认面板可适当宽于应用窗口，使三个操作保持一行。弹出时焦点落在「保留后台」，按 Esc 回到当前应用。

| 选择 | 结果 |
|---|---|
| 保留后台 | 关闭窗口并释放虚拟显示。Android 保留活动任务期间，可从「运行中」恢复窗口。 |
| 完全退出 | 结束本实例中的目标应用，核实进程已停止、最近任务已移除，再关闭窗口。退出失败时保留原窗口并提示原因。 |
| 取消 | 保留窗口和当前操作。 |

「记住选择，用于所有应用」默认不勾选。勾选后选择「保留后台」或「完全退出」，会保存为所有实例共用的应用窗口关闭偏好，可在「设置 → 应用窗口」更改。取消会保留原偏好。持久化时区分尚未选定和已记住的操作，单次关闭只处理当前窗口。

应用已结束时直接回收窗口。窗口异常退出时先报告错误。其余情况依已保存的偏好执行，没有保存偏好时询问。关闭设备视图只结束该路显示，实例及其余窗口继续运行。

## 五、首次启动与运行时准备

### 首次打开与手动引导

产品开关 `showGuideOnFirstLaunch` 决定全新工作区的入口。默认直接打开「全部实例」。启用后先显示欢迎页，可选「开始设置」或「直接进入」。两种入口共用同一套资源准备流程，即使没有安装组件、下载镜像或创建实例，仍可浏览主窗口并调整存储位置。

「设置」标题栏常驻「引导」入口，在任意设置分类中均可打开。普通设置页不提供首开策略开关。首次进入后记录已展示过首个页面，重开工作区时恢复最近使用的有效实例，零实例则打开「全部实例」。升级时先识别已有工作区。跳过、删除最后一个实例或后来调整产品开关，都不会重新触发首次欢迎页。

### 引导分支

| 当前步骤 | 用户继续 | 用户跳过 |
|---|---|---|
| 欢迎 | 检查受管运行组件。已就绪则直接选择系统镜像 | 直接进入工作台 |
| 运行组件 | 展示项目名称、下载大小、许可和存储位置。用户确认下载、安装完成后，可继续选镜像 | 结束本轮引导，略过镜像和实例创建 |
| 系统镜像 | 显式选用本机已有镜像，或选定版本、同意下载并等其就绪，再进入创建表单 | 结束本轮引导，保留已有镜像，实例数不变 |
| 创建实例 | 用户确认名称、设备、硬件和用户空间后创建，打开新实例的页面 | 放弃本次创建，保留已准备的组件和镜像 |

首次进入或从空列表打开引导，跳过后回「全部实例」。从「设置」手动打开引导，跳过后回原设置分类。已明确发起的下载在退出引导后继续，完成时更新本机资源。关闭程序后保留下载进度，重开可手动继续。单独下载镜像只准备资源，创建实例需要用户另行确认。

### 离开引导后的工作台

零实例时，侧栏保留「实例」「运行环境」「设置」。空列表依据本机状态给出下一步。缺组件时可查看并准备组件，下载中可查看进度，组件就绪后可创建实例。打开工作区时可以检查本机资源。浏览和调整设置始终可用，缺少前置资源只会阻止依赖它的操作。每次下载均由用户明确发起。

**原生实现进度。** 当前客户端先判断运行环境，再判断是否已有实例。准备清单中含 Android 14 镜像。双模式与分步跳过已在交互原型中提供。[原生窗口路由](../../app/App.tsx) · [原生准备清单](../../crates/runtime/src/provision/catalog.rs)

### 组件、系统镜像与存储位置

运行组件由 Windroid 统一安装。组件清单直接列出 Android Emulator、Android SDK Platform-Tools、Android SDK Build-Tools 和 scrcpy-server 的版本、大小和许可。发布版使用受管工具。开发期可显式指定已有 SDK。[运行组件与发布清单](../架构/01-运行环境域.md#二发布组件)

系统镜像按版本列出「本机可用」和「可下载」。创建实例时可以复用已有镜像，也可确认许可、下载所需版本后创建。多个实例共用只读镜像，每个实例保有独立的应用和用户数据。本地导入按内置清单核验官方完整 ZIP，匹配后展示版本、修订、ABI 和许可供确认，已准备的镜像可直接复用。原型提供 Android 14 Google Play ARM64 修订版 14 的导入样例。清单外镜像的参数识别与兼容性验证仍待评估。

「设置 → 存储位置」显示主数据目录、运行组件目录和系统镜像目录。主数据目录默认在 `~/.windroid`，存放实例、设置与日志。所有核心运行组件共用一个可更改的目录，默认位于主数据目录下。系统镜像默认跟随运行组件，也可单独选择目录。迁移已有资源前，列出将要移动的文件及新旧位置。等待相关下载完成、占用资源的实例停止后，再移动并更新目录设置。

## 六、资源治理

创建实例时确定单台规格，在启动或恢复时检查所有活动实例的合计分配。CPU 预算取本机逻辑核数，客户机内存预算取本机物理内存的 50%。可同时运行的台数还取决于宿主当时的内存余量和可用端口。

- **用户空间。** 创建时提供 6、8、16、32 GiB 和自定义整数。通常默认 8 GiB，上限取实例数据所在卷可用空间的 70%，向下取整到 GiB。仅剩 6–7 GiB 可分配时默认 6 GiB，低于 6 GiB 时提示释放空间。配置值表示用户数据分区容量。创建后维持该容量，避免重建分区损失数据。[用户数据分区实测与创建检查](../架构/01-运行环境域.md#七实例存储)
- **创建或停止后调整硬件。** 处理器默认 2 核，可选常用档位或自定义整数。单台从 1 核起，上限取 Emulator、虚拟机机型、虚拟化框架和本机逻辑核数所允许的最小值。单台内存上限取机型上限与物理内存 50% 的较小值。内存下限由受管 Emulator 版本、镜像规格和最终设备配置共同决定。导入镜像与内置镜像使用相同规则。无法确认兼容性时，指出缺少的规格。可保存符合单台限制的配置，保存时不占用活动额度。[内存下限及输入来源](../实测/01-运行环境域.md#82-客户机内存下限)
- **启动或恢复。** 本次 vCPU 加上已预留的 vCPU 可以等于本机逻辑核数，超过就拒绝本次启动。内存按模拟器实际将分配给客户机的容量计算，必须同时满足共享预算余额和宿主当前可新增的客户机内存估计。严重内存压力直接拒绝，警告级仍检查两个余额。宿主观测缺失或过期时重新读取，仍无法判断则提示重试。拒绝只影响本次请求。CPU 的 1∶1 是 Windroid 的多开策略，宿主内存估计的安全余量还需要跨机型标定。[CPU 来源与并发验证](../实测/01-运行环境域.md#81-单实例-vcpu-与并发分配) · [宿主内存预算的依据](../实测/01-运行环境域.md#83-单实例内存上限与宿主预算)
- **并发与重启。** 计算余额时计入正在启动、正在运行、正在停止且资源尚未释放的实例。并发请求逐台校验并预留，宿主内存估计只补扣采样后新增的预留。批量操作先列出逐台预检结果，实际启动时再查。重启先按替换本实例预检，已知不能启动时保留当前会话。原进程退出后按实际余量复核。
- **空闲冻结**适用于未选中的运行实例。连续 10 分钟无交互、无窗口时，Windroid 停止该实例并回收内存。核实快照已保存后，侧栏显示「已冻结」，可点击恢复。
- **应用窗口**单独限制为最多 8 个。窗口关闭后的后台策略不改变实例的内存分配。

**原生实现进度。** 当前宿主在创建和启动时按存活实例的模板内存检查 50% 预算，启动另限 3 台。vCPU 合计预留与宿主实时内存余量检查仍待接入。[当前宿主检查](../../crates/host/src/library/commands.rs) · [预算来源及实测范围](../实测/01-运行环境域.md#83-单实例内存上限与宿主预算)

## 七、安装

实例就绪后，可将 APK 拖到应用面板或点击「安装 APK…」选择文件。拖放以放下文件时的实例为目标，文件选择器在打开时绑定发起实例。此后即使切换实例，安装命令、进度与最终结果仍属于原定目标。遇到 `INSTALL_FAILED_*` 时显示中文原因，并提供原始输出供核查。原安装包保持原样，是否换包或重试由用户决定。Windroid 保留系统现有的 APK 文件关联。

键盘用户可从「安装 APK…」完成选择和确认，也可从「运行中」恢复后台应用。窄窗中截断的名称应可查看全名。浅色和深色外观均需检查选中态、禁用态及键盘焦点，操作后焦点应回到对应实例。在 macOS 原生客户端用 VoiceOver 核验控件名称、焦点顺序、确认框与结果提示。

## 八、非目标

- 主窗口以实例和应用管理为中心，整机画面通过按需打开的设备视图提供。
- 插件系统、通用配置抽象、跨平台统一图形抽象和与 Android Studio 对等的 AVD 管理器不在当前范围。
- 实例媒体音量属于单台 Android 的设置。独立音频面板、通知桥接、剪贴板、多显示器映射留待 v1 之后评估。

## 九、与里程碑的关系

各切片的用户验收目标如下。工程依赖和平台进度见[架构里程碑](../架构总览.md#9-里程碑)。

| 切片 | 用户拿到什么 |
|---|---|
| S1 运行时准备 | 首次打开能自检、能装、能建实例 |
| S2 实例管理 | 侧边栏看实例、启停、看真实进度 |
| S3 应用库 | 看到应用网格、能安装 APK |
| S4 应用窗口 | 点应用，独立窗口打开它 |
| S5 关闭语义与运行中 | 关窗可控、运行中可管 |
