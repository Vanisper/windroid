# 全部实例批量启停

2026-11-21，在 Apple M4、10 个逻辑核、16 GiB 内存、macOS 27.2.1 上验收。批量操作从 Windroid 原生窗口发起。宿主拒绝、客户机状态和文件保留分别按结果页、ADB 服务和私有盘回读核对。

## 两台真实 Android 实例

在全新的 `WINDROID_HOME` 中预放官方展开资源，经原生窗口确认建库，创建「我的 Android」和「Android 2」。两台都使用 Google Play ARM64 API 33 r9、2 核、2048 MiB、8 GiB 用户空间。运行组件为 Emulator 37.2.13、Platform-Tools 37.0.1、Build-Tools 34.0.0 和 scrcpy-server 5.0.1。客户端使用独立的 Android 用户目录和 ADB 服务。操作前用注册记录与客户机的 `ro.boot.qemu.avd_name` 核对身份。

| 操作 | 实际观察 |
|---|---|
| 从侧栏「实例」进入，未勾选时点「全部启动…」 | 列表顺序为「Android 2」「我的 Android」。第一次预检中，预计第一台启动后，第二台的宿主可分配量只剩 1791 MiB。点击「重新检查」后两台都可启动。确认后先看到第一台正在启动、第二台等待，随后两行均显示「成功 · 已启动」。 |
| 在后续一轮再次启动两台 | 确认时两台均可执行。第一台成功，第二台执行时宿主预计只可分配 2017 MiB，结果显示它需要 2048 MiB。「重试失败项…」只列「我的 Android」，重试后该实例就绪。此处用的是当时本机的真实余量。 |
| 在「我的 Android」打开设备视图和系统设置窗口；在「Android 2」打开 Windroid Alpha | 两台共显示三个客户机窗口。勾选「我的 Android」，进该行设置再返回，仍显示已选 1 个。停止确认列出该实例的「设备视图、设置」，并提示将结束后台任务。 |
| 确认停止所选实例 | 结果只有「我的 Android」。该实例两个窗口均关闭，独立 ADB 服务只剩 `emulator-5556`。「Android 2」的 Alpha 原窗口继续显示，点击其中的计数按钮，读数从 1 变为 2。 |
| 确认后制造端口冲突，再重试 | 两台中只有「我的 Android」已停。从「全部启动…」预览后，用临时 TCP 监听器占用其 5554 端口，再确认。结果一行「已跳过 · 已在运行」，另一行报告端口对 5554/5555 被占用。释放监听器后，重试确认页只列「我的 Android」。它恢复就绪，另一台的 QEMU PID 和 ADB transport ID 均保持原值。这次冲突由测试主动制造，客户端和模拟器均为真实进程。 |
| 核查数据 | 停止前在「我的 Android」写入 `/data/local/tmp/wd-batch-proof`。重启和失败重试后，文件仍为 `windroid-batch-a-1121`，Android 的 `boot_count` 仍为 1。「Android 2」没有这个文件。两台的 Activity、Package、Window 三个服务均可回读。 |

在第二个全新工作区，用 `cd89c9f` 复核只读端口检查。确认前临时监听 IPv6 通配地址的 5555 端口，「我的 Android」预检显示 5554/5555 已占用。释放监听器并重新检查后，端口冲突消失，第二台按当时的预计余量跳过。第一台就绪后，从整表再次启动，已运行的一台跳过，第二台就绪。侧栏实例行在停止、等待 ADB 和就绪时实测均为 45 pt。macOS 辅助功能树中，「重新检查」的值包含范围、每行结论与关窗影响，结果行的名称入口提供该行结果，「完成」提供汇总。辅助功能核验采用系统树回读。[只读端口检查](../../crates/runtime/src/instances/ports.rs) · [原生确认与结果](../../app/ui/batch.tsx)

### 停止先启动的实例

在 Emulator 37.2.13 上，两台同时就绪后，停止先启动的实例曾导致另一台 QEMU 一并退出。故障时两台连接同一个 netsim gRPC 端点。独立回归用例在 `7f4509e` 重现了故障：第二台进程退出，Activity、Package、Window 三个服务都变为不可用。修复后，两台分别使用自己的服务与临时目录，用例连续五次读到同一 Android 内核启动 ID 和三个就绪服务，且仍有到宿主的 IPv4 路由。[真实模拟器回归](../../crates/runtime/tests/real_emulator.rs) · [运行时隔离](../../crates/runtime/src/instances/process.rs)

用 `1c46aab` 的签名客户端再次从全部实例启动，「Android 2」先就绪，「我的 Android」后就绪。两份 `netsim.ini` 记录的服务 PID 分别为 57127、57608，gRPC 端口分别为 57440、57608。两台同时在线时，在「我的 Android」打开 Alpha，在「Android 2」打开设备视图和设置。

| 原生操作 | 核查结果 |
|---|---|
| 勾选先启动的「Android 2」，进管理页再返回，确认停止所选 | 确认只列「Android 2」和它的两个窗口，结果为成功 1 个。两个窗口关闭。未选的「我的 Android」保留原内核启动 ID 和 Alpha 窗口，在原窗口点击后计数从 0 变为 1。通过 Android 的 `wlan0` 向宿主临时 TCP 服务发起连接，收到约定的回包。 |
| 再点「全部启动…」 | 「我的 Android」因已运行而跳过。「Android 2」恢复就绪，从其私有盘读回停机前写入的 `peer-first-marker`，无线服务使用了新的临时目录和端口。两台均可收到宿主 TCP 回包。 |
| 两台均就绪时点「全部停止…」 | 确认列出两台，并提示将关闭「我的 Android」的 Alpha 窗口。结果逐行显示「成功 · 已停止」，汇总为成功 2 个、跳过 0 个、失败 0 个。客户机窗口全部关闭，两台本轮的无线服务和临时目录均已回收。 |

### 复核步骤

复核时，构建应用并使用新工作区。将测试用官方组件放入工作区的 `runtime`、镜像放入 `system-images`。以下命令为这次客户端单独启动 ADB 服务，关闭对其他工作区模拟器端口的自动扫描。脚本退出前应从列表停止测试实例，再关闭客户端。

```sh
out="$PWD/build/batch-instance-actions"
bash scripts/package-macos.sh "$out"
run=$(mktemp -d /private/tmp/wd-batch.XXXXXXXX)
export WINDROID_HOME="$run/workspace" ANDROID_USER_HOME="$run/android"
mkdir -p "$WINDROID_HOME/system-images" "$ANDROID_USER_HOME" "$run/user" "$run/tmp"
# WINDROID_TEST_RESOURCES 指向官方展开资源的父目录。
cp -cR "$WINDROID_TEST_RESOURCES/runtime" "$WINDROID_HOME/runtime"
cp -cR "$WINDROID_TEST_RESOURCES/system-images/android-33" "$WINDROID_HOME/system-images/"
export ANDROID_ADB_SERVER_PORT=$(python3 -c 'import socket; s=socket.socket(); s.bind(("127.0.0.1",0)); print(s.getsockname()[1])')
export ADB_SERVER_SOCKET="tcp:localhost:$ANDROID_ADB_SERVER_PORT" ADB_LOCAL_TRANSPORT_MAX_PORT=5553
HOME="$run/user" TMPDIR="$run/tmp/" WINDROID_FAKE=0 "$out/Windroid.app/Contents/MacOS/windroid"
"$WINDROID_HOME/runtime/platform-tools/37.0.1/adb" kill-server
```

未选实例的可操作性用仓库内的 Alpha 测试 APK 验证。安装到该实例后，点击应用面板的「刷新列表」，再从「打开 Windroid Alpha」进入其独立窗口。[APK 构建脚本](../../scripts/build-test-apks.sh) · [计数按钮与持久化逻辑](../../scripts/android-fixture/MainActivity.java)
