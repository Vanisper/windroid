在 Android 14 Google Play 私有实例中，Rust 客户端同时解出了主屏的 864×1920 非黑帧，以及 Beta 虚拟显示的 720×1280 非黑帧。关闭主屏会话后，应用会话继续响应按键并输出帧。[双显示测试](../../crates/stream/tests/real_stream.rs)

## A. 握手

### A1. 连接与字节序列

**adb tunnel 默认 reverse**（client 监听、device 连接），`--force-adb-forward` 时用 forward。

按顺序打开最多 3 个 socket：**video → audio → control**（可分别禁用）。

在**第一个**被打开的 socket 上：

1. 若为 forward 连接，device 先发 **1 个 dummy byte**（值 0，用于让 client 探测连接错误）
2. 然后发 **64 字节固定长度 device name**（UTF-8、无长度前缀、`\0` 填充）

出处：`DesktopConnection.java` L64-90、L155-165；`app/src/server.c` L596-610；`server.h` L16（`SC_DEVICE_NAME_FIELD_LENGTH 64`）

**注意**：dummy byte 仅在 forward 时发送；device name 是定长 64 字节，不是「长度前缀 + 变长字符串」。

### A2. 流开始的 header

- video / audio socket 各自先发 **4 字节 codec id**（u32 大端、ASCII）
- video 接着发 **12 字节 session packet**（见 B4）；audio **没有** session packet，codec id 后直接是 media packet

出处：`demuxer.c` L56-65、L67-133

### A3. 版本协商：严格相等，无兼容

server 的第一个命令行参数是 client 版本，与 `BuildConfig.VERSION_NAME` 做 `equals` 比较，不等则抛 `IllegalArgumentException` 退出。**协议里没有运行时版本字段。**

出处：`Options.java` L320-333

**影响**：server 与 client 版本必须严格配对。这强化了「scrcpy-server 是二级组件、跟 app 版本走」的决策——不存在「兼容多个 server 版本」的余地。

## B. 视频包格式

### B4. packet header：12 字节

首字节 **bit7（MSB）**：
- `1` = **session packet**（12 字节 header，无 payload）
- `0` = **media packet**（12 字节 header + `packet_size` 字节 payload）

session packet 的宽度位于 `hdr[4..8]`，高度位于 `hdr[8..12]`。实测 1920×1080 设备所得两字段分别为 1920 和 1080。解析时跳过前 4 字节的标志位，首次连接和客户端调整尺寸共用该布局。[分包实现](../../crates/stream/src/packet.rs)

media packet 的 12 字节 = 8 字节 PTS+flags + 4 字节 packet size：

```
bit63 = PACKET_FLAG_SESSION   (1<<63)   会话包
bit62 = PACKET_FLAG_CONFIG    (1<<62)   SPS/PPS 等配置
bit61 = PACKET_FLAG_KEY_FRAME (1<<61)   关键帧
低 61 bit = PTS(微秒)
```

出处：`Streamer.java` L17-19、L107-124；`demuxer.c` L14-15、L135-183

### B5. 关键帧标志

media packet header 的 bit61。client 映射为 FFmpeg 的 `AV_PKT_FLAG_KEY`。出处：`demuxer.c` L177-179

### B6. codec id 取值

| 类型 | 值 |
|---|---|
| h264 | `0x68323634` |
| h265 | `0x68323635` |
| av1 | `0x00617631` |
| vp8 | `0x00767038` |
| vp9 | `0x00767039` |

音频：opus=`0x6f707573`、aac=`0x00616163`、flac=`0x666c6163`、raw=`0x00726177`

特殊值：`0` = 显式禁用该流；`1` = 配置错误（client 必须停止）

出处：`VideoCodec.java`、`AudioCodec.java`；`demuxer.c` L21-29

### B7. 分片与重组

**协议本身不做跨 packet 分片**。每个 media packet 的 payload 是 MediaCodec 输出的一个完整 buffer，由 header 的 packet size 界定，client 一次性收完。

「重组」只发生在一种情况：**H.264/H.265 的 config packet 需要前置拼接到下一个 media packet**（`sc_packet_merger`）。

出处：`demuxer.c` L277-286、L316-323；`packet_merger.c/h`

## C. 编码参数

### C8. 参数传递方式

**不是运行时消息，而是启动 server 时的命令行 key=value 参数**：

| 参数 | 含义 |
|---|---|
| `max_size=<u16>` | 分辨率上限（-m） |
| `video_bit_rate=<u32>` | 码率 bps（-b） |
| `max_fps=<float>` | 帧率上限（--max-fps） |
| `video_codec` | 编码格式 |
| `crop` / `angle` / `capture_orientation` | 裁剪与方向 |
| `display_id` | 镜像哪个 display |
| `new_display=<规格>` | 创建虚拟 display |

出处：`app/src/server.c` ADD_PARAM 段 L300-460；`Options.java`

**影响**：所有编码参数在启动时定死，运行中改不了。要改必须重启 server 会话。

### C9. 默认编码器选择与降级

有 `video_encoder` 时 `createByCodecName` + 校验 mime；否则由系统 `MediaCodec.createEncoderByType()` 选。

失败时 `downsize_on_error`（默认 true）按 `{2560, 1920, 1600, 1280, 1024, 800}` 逐级降低分辨率重试。

出处：`SurfaceEncoder.java` L280-308、L191-250、L310-348

## D. 输入注入

### D10. 触摸事件格式（INJECT_TOUCH_EVENT，type=2，33 字节）

```
type(1B) + action(1B) + pointer_id(8B u64) + position(12B)
  + pressure(2B u16 定点) + action_button(4B u32) + buttons(4B u32)

position(12B) = x(i32) + y(i32) + screen_width(u16) + screen_height(u16)
```

指针 id 特殊值：mouse=`UINT64_MAX`、finger=`UINT64_MAX-1`、virtual finger=`UINT64_MAX-2`

pressure 用 `sc_float_to_u16fp`（0..1 → 0..65535）

出处：`control_msg.c` L118-127、L68-73；`control_msg.h` L21-27、L73-80

### D11. 坐标：绝对像素，不是归一化

**这是关键的纠正**：坐标是**绝对像素值（int32）**，以视频帧为参照，不是 0–65535 归一化。

position 里携带 `screen_size`，server 端 `PositionMapper` 把帧坐标映射为设备像素坐标。若 `screen_size` 与当前 videoSize 不符（例如设备刚旋转），**事件被丢弃**。

出处：`coords.h` L16-22；`input_manager.c` L386/741/805；`PositionMapper.java` L34-46

### D12. 其它输入类型

| 类型 | type | 大小 | 结构 |
|---|---|---|---|
| 键盘 | 0 | 14B | type + action(1B) + keycode(u32) + repeat(u32) + metastate(u32) |
| 文本 | 1 | 变长 | type + 长度(4B) + UTF-8（上限 300） |
| 滚轮 | 3 | 21B | type + position(12B) + hscroll(i16 定点) + vscroll(i16) + buttons(u32) |
| 设置剪贴板 | 9 | 变长 | type + sequence(u64) + paste(1B) + len(u32) + text |
| 获取剪贴板 | 8 | 1B | type + copy_key(1B) |

滚轮的 hscroll/vscroll 范围 [-16, 16]，归一化为 i16 定点。

设备→client 的消息：CLIPBOARD(type 0) + ACK_CLIPBOARD(type 1) + UHID_OUTPUT(type 2)

出处：`control_msg.c` L107-141；`device_msg.c` L17-73

### D13. 通道分离

输入事件走**独立的 control socket**，与 video / audio 分离。control 是唯一双向通道（输入下行、剪贴板上行）。

出处：`develop.md`；`receiver.c`；`controller.c`

## E. 控制通道与生命周期

### E14. 建立时机

启动时按 video → audio → control 顺序建立，无独立额外握手。仅「第一个 socket」收到 dummy byte（forward 时）+ 64 字节 device name。client 对 control 设 `TCP_NODELAY`。

出处：`server.c` L628-718；`DesktopConnection.java` L56-116

### E15. 断开感知：靠 EOF，无特定消息

- video / audio：demuxer 的 recv 失败置 EOS，回调 `on_ended`
- control：receiver 的 recv ≤ 0（error=false）则 break，回调 `on_ended`

出处：`demuxer.c` L296-299；`receiver.c` L197-200、L218

**影响**：不存在「断开通知包」。设计上必须把 `recv` 返回 ≤ 0 当作断开信号，并区分「错误断开」与「正常 EOF」。

### E16. 旋转 / 分辨率变化：通过 session packet

**没有独立的控制消息**。分辨率变化通过 video 流中的 **session packet**（首字节 MSB=1 的 12 字节 header）表示新编码会话：server reset 并重启 MediaCodec，重发 session packet（含新的 width/height）。

byte3 的 bit0 表示 client-resized（flex display 下 client 触发 resize）。

client 收到后重建 decoder / display。**codec id 只发一次**。

出处：`SurfaceEncoder.java` L104-152；`Streamer.java` L91-105；`demuxer.c` L302-309

## F. 音频与多显示器

### F17. 音频是独立通道

独立 audio socket（默认 OPUS）。header 只有 4 字节 codec id，**没有 session packet**；之后是 12 字节 header + payload，格式与视频相同。固定 stereo / 48000Hz。捕获失败时写 codec id = 0 或 1。

出处：`AudioEncoder.java` L117-132；`Streamer.java` L39-46；`demuxer.c` L261-270

### F18. 多显示器：可切换镜像目标，不是并行多流

- `display_id=<u32>`：镜像指定的 display
- `list_displays=true`：打印可用 display 列表
- `new_display=<规格>`：**创建虚拟 display**，`vd_*` 控制内容与装饰

**关键**：这不是「同时推多路流」，而是「选择某一块 display 来镜像」+「可创建虚拟 display」。单一 server 会话只推一路视频。

出处：`server.c` L444-448、L336-339；`DisplayManager.java`、`DisplayInfo.java`、`DisplayMonitor.java`
