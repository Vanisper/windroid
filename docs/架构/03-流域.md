# 流域设计

流域将一块 Android 显示的画面送入一个 macOS 原生窗口，并将该窗口收到的输入送回同一块显示。设备端运行固定版本的 scrcpy-server 5.0.1，主机端的 Rust client 负责连接、分帧和调用 VideoToolbox。应用包只需分发自己的可执行文件及界面，Android 组件由运行环境域准备。[运行环境域](./01-运行环境域.md) · [呈现域](./04-呈现域.md)

## 窗口与显示的对应关系

| 打开入口 | Android 显示 | 启动行为 |
|---|---|---|
| 设备窗口 | 已有主屏，display 0 | 镜像主屏，保留当前前台内容 |
| 应用库中的应用 | 为该窗口创建虚拟显示 | 从此次 server 的日志取得实际显示 ID，通过它的 control socket 向目标包发送一次 START_APP |
| 同一实例中已开窗的应用 | 复用原窗口及显示 | 窗口管理器聚焦已有窗口 |

应用显示初始为 720×1280、240 dpi。server 启用灵活尺寸，关闭系统装饰，输入法按本地显示处理。应用是否已在目标显示运行，以 Android 回读的包名和显示 ID 为准。设备主屏和不同应用可同时拥有各自的编码器、控制通道和显示内容。显示 ID 由 Android 分配，只在该显示存活期间使用。源码依据见 [NewDisplayCapture](https://github.com/Genymobile/scrcpy/blob/v5.0.1/server/src/main/java/com/genymobile/scrcpy/video/NewDisplayCapture.java) 和 [Controller](https://github.com/Genymobile/scrcpy/blob/v5.0.1/server/src/main/java/com/genymobile/scrcpy/control/Controller.java)。

## 从打开请求到首帧

1. 窗口后台线程调用 `VideoSession::start_cancellable`，传入该实例的 adb、serial、5.0.1 JAR 和显示目标。流域生成独立的 31 位 scid，以独占目录保存设备端 JAR 与 PID。adb 为本会话分配本地 TCP 端口，映射到该 scid 的 abstract socket。
2. 启动设备端 server。主屏指定 `display_id=0`，应用指定 `new_display`。协议版本由 server 在启动时严格核对。
3. client 先连接视频 socket，确认 forward 模式的一个探测字节，再连接控制 socket。此后从视频通道依次读取 64 字节设备名、4 字节 codec ID、12 字节会话头。本实现使用 H.264，关闭了音频。连接与元数据握手共用 12 秒期限。[DesktopConnection](https://github.com/Genymobile/scrcpy/blob/v5.0.1/server/src/main/java/com/genymobile/scrcpy/device/DesktopConnection.java) · [Streamer](https://github.com/Genymobile/scrcpy/blob/v5.0.1/server/src/main/java/com/genymobile/scrcpy/device/Streamer.java)
4. 对应用目标，client 取得本次 server 的虚拟显示 ID，在发送 START_APP 前检查窗口的取消请求。server 在对应显示上启动包。这一步只确认消息已发出。窗口协调器另行观察该包在该显示上的 Activity。
5. `VideoSession::run` 读取媒体包。首帧须在 15 秒内解出。随后允许静止画面无限期停在最后一帧。控制通道断开会唤醒正在等待视频数据的线程。[连接与接收](../../crates/stream/src/lib.rs) · [server 资源管理](../../crates/stream/src/server.rs)

## 解码与尺寸变化

每个视频包以 12 字节大端头开始。client 在分配之前检查媒体负载长度和帧的像素总数。收到会话包时更新流尺寸，重建解码器。媒体数据按 Annex-B 分离 NAL 单元，缓存 SPS/PPS，并在获得可解码的 IDR 后将长度前缀样本交给 VideoToolbox。解码器按实际行跨度复制成连续 BGRA，随帧返回宽、高。窗口线程通过有界的最新帧槽显示画面，绘制落后时以新帧覆盖旧帧。[分包](../../crates/stream/src/packet.rs) · [H.264 解码](../../crates/stream/src/decode.rs) · [VideoToolbox 接口](../../crates/stream/src/videotoolbox.c) · [窗口后台线程](../../app/src/streaming.rs)

拖动应用窗口改变尺寸后，呈现层在调整结束时发出 resize。实际生效尺寸以后续会话包和已呈现帧为准。设备窗口的缩放只改变主机端画面布局。

## 输入与退出

表面根据当前显示帧及其在窗口中的等比矩形，将指针位置换算为绝对像素，过滤黑边。流域检查坐标及所附帧尺寸，向该窗口专属的 control socket 写按键、文本、触控或滚轮消息。旋转或调整尺寸后，仍引用旧尺寸的指针事件会被丢弃。键盘输入沿同一窗口的通道发送。协议布局见 [control_msg.c](https://github.com/Genymobile/scrcpy/blob/v5.0.1/app/src/control_msg.c)，实现见[控制通道](../../crates/stream/src/control.rs)。

关闭窗口会取消握手或 shutdown 已连接的 socket。会话所有者回收自己的 adb 子进程、设备端进程、forward 和暂存目录。移除 forward 前匹配 serial、本地端口与目标 socket，向远端 PID 发信号前核对本会话的 CLASSPATH。主动关闭按正常结束处理，设备端退出、通道断开或包解析失败会报告到所属窗口。彻底退出应用的任务及进程回读由设备侧操作负责。[窗口关闭契约](./04-呈现域.md)

## 验证范围

- **协议与系统解码实测**。在 macOS 上运行下方第一条命令。回环 fixture 使用独立的设备和应用会话，核对 START_APP、输入字节、静止时控制通道断开、关窗取消、资源回收和尺寸变化。真实 VideoToolbox 解出的已知红蓝帧同时校验尺寸和像素。[协议回归](../../crates/stream/tests/protocol.rs)
- **模拟器验收**。下方第二条命令使用已启动的私有测试实例及已安装应用。它要求主屏和应用显示的 ID 正确、两路均解出非黑帧，并在关闭主屏后向应用发送按键并取得后续帧。请在测试输出中核对实际显示 ID 与两路测试结果。[双显示测试](../../crates/stream/tests/real_stream.rs)
- **历史实测**。M1a 观察到真实的 1920×1080 模拟器画面。协议字节序列、历史实验环境和上游版本单独保存在[协议实测记录](../实测/03-流域.md)。持续帧率、并行窗口负载及特定 Android 应用对多显示的支持应在目标设备上测量。

```bash
cargo test -p stream --test protocol

# WINDROID_SERIAL 为该测试实例的实际 serial；WINDROID_TEST_ADB 和 WINDROID_TEST_SERVER_JAR 分别指向实际 adb 和 5.0.1 JAR。
# WINDROID_STREAM_PACKAGE 可选，默认为 com.android.settings。
cargo test -p stream --test real_stream -- --ignored --nocapture
```
