# 运行时组件设计

## 本文档边界

本文覆盖 Windroid「运行环境域」的设计规格：运行时组件分级与版本策略、镜像源抽象、目录布局与安装契约、实例创建与 AVD 生成、实例存储能力、端口分配、失败分类与验收标准。

不覆盖：窗口/视频/输入链路（属流域与呈现域）、应用语义与设备能力（属设备域）、界面视觉规范。当前发布契约以组件清单和实例注册表为准。

支撑本文结论的实测证据见 [实测/01-运行环境域](../实测/01-运行环境域.md)。上一级文档见 [架构总览](../架构总览.md)。

标注约定：**实测** = 本机验证过；**源码依据** = 来自上游源码；**推断** = 未验证的判断，需后续确认。

## 一、运行环境域的定位

**职责**：让「启动一个 Android 实例」从零开始可用。管理运行时组件、系统镜像、实例存储、端口分配、进程启停。

**不负责**：窗口/视频/输入（属流域与呈现域）、应用语义（属设备域）。

**核心约束**：在零运行时、零镜像的状态下，界面必须完全可达；每次下载须由用户从运行环境、创建实例或引导流程中明确发起。

## 二、发布组件

当前原生版首次准备面向 Apple 芯片的 Mac，所有实例共用已安装的模拟器、工具、协议服务和只读系统镜像。运行时清单随应用发布，记录每个档案的来源、版本、下载字节数、解压体积、摘要和许可证。四个运行组件的下载总量为 509,516,883 字节。Android 13、14、15 的 Google Play ARM64 系统镜像分别准备。[组件清单及上游元数据来源](../../crates/runtime/src/provision/catalog.rs)

| 组件 | 作用 |
|---|---|
| Android Emulator、platform-tools | 启动实例、按 serial 连接设备。 |
| build-tools | 提供 aapt，从主机侧读取 APK 资源中的标签等信息。准备时下载其完整上游档案。 |
| scrcpy-server 5.0.1 | 应用固定与 client 配套的协议版本。每条显示会话推送独立副本。[流域设计](./03-流域.md) |
| Android 系统镜像 | 多实例共用只读镜像，首次启动时以它初始化各自的用户分区。 |

**版本实测**。镜像的 `source.properties` 中，`Pkg.Dependencies=emulator#X.Y.Z` 指定最低版本。历史实验中，emulator 37.2.13 成功运行了要求 34.2.16 的镜像。[版本记录](../实测/01-运行环境域.md)

## 三、镜像来源

当前清单中的 Android 档案来自 Google，scrcpy-server 来自 Genymobile 的 5.0.1 发布。界面提供每项的来源与许可。设置中可选择已经解压的版本目录，核验后从原位置使用。[运行时路径解析](../../crates/runtime/src/provision/paths.rs)

镜像身份由 API、标签、ABI、官方包修订四项组成，创建时写入实例清单，每次启动按同一身份解析。准备某个镜像只操作该版本。目录自检核对包的修订、API、标签、ABI、发布者、最低 Emulator 版本和启动文件。[产品交互与存储位置](../产品/01-产品形态与交互.md#组件系统镜像与存储位置)

从本机选择 ZIP 时，先比对清单的字节数与摘要，再读取包内元数据核对身份和兼容要求。确认仅安装所选镜像，已就绪的版本可以复用。安装前重新复制并校验本地文件，失败时保留先前下载的可续传部分。[本地档案预览与导入](../../crates/runtime/src/provision/import.rs)

下载源切换属于后续评估项。若引入多源，需分别处理元数据地址和包地址。下表记录调研时的连通性与传输情况。

## 四、目录布局

默认工作区为 `~/.windroid`，可通过 `WINDROID_HOME` 选择。两个资源根分别保存绝对路径，下图展示默认值。

```text
~/.windroid/
├── workspace-format                  内容为 windroid-workspace-v1，末尾一个 LF
├── storage.json                      自选的运行组件根、镜像根
├── .storage-migration.json           迁移期间的事务记录（schema 为 1）
├── storage-cleanup/                  待复核和清理的迁移副本记录
├── runtime/
│   ├── emulator/37.2.13/
│   ├── platform-tools/37.0.1/
│   ├── build-tools/34.0.0/
│   └── scrcpy-server/5.0.1/scrcpy-server.jar
├── system-images/android-34/google_apis_playstore/arm64-v8a/r14/
├── instances/<id>/
│   ├── instance.json                 身份、镜像修订、AVD 名及端口
│   ├── avd/                          私有配置、数据盘及快照
│   └── emulator.log
├── cache/
└── preferences/
```

每次打开工作区都先只读检查，再写首屏记录、取得注册表锁或恢复待处理的事务。

| 所选路径 | 打开条件 |
|---|---|
| 尚未创建或为空 | 在该位置建立工作区并写入 `workspace-format`。 |
| 已有 `workspace-format` | 核对标记、控制文件、实例注册表、存储设置和迁移事务。根下的 `runtime` 与 `system-images` 可缺省，存在时须为可读取和进入的普通目录，资源改存其他位置后也适用。无关的用户文件可以保留。 |
| 非空且缺少 `workspace-format` | 仅包含按版本目录预放的官方组件或镜像时，完整核验后供用户预览。确认建库时重新检查，再写入格式标记。其他内容保持原样。 |

检查失败时，原生窗口展示实际路径和失败原因。「选择其他目录…」将新路径送回同一检查入口，通过后以该路径作为本次运行的工作区。下次启动仍从 `WINDROID_HOME` 或默认路径开始。[格式检查](../../crates/runtime/src/workspace.rs) · [原生启动入口](../../app/src/main.rs)

设置先显示本次切换涉及的源、目标、实例依赖和各完整版本。可预选未来位置、复用齐全的目标或迁移缺失的版本。复制在目标卷暂存，校验后改名发布，最后提交新设置。目录切换结束时立即释放工作区的操作锁。运行中的模拟器和窗口继续持有所用版本的读锁，直至使用结束。选择清理原版本时逐项复核，离线、正在使用或内容已变化的原件会保留。[位置设置](../../crates/locations/src/lib.rs) · [预览与恢复](../../crates/runtime/src/storage.rs)

macOS 将卷 UUID 与挂载点记录在工作区。迁移预览、确认与事务记录另以卷 UUID、文件 ID 和创建时间识别已核验的版本目录及暂存对象。清理前同时核对源与目标的身份和完整内容，回滚前也要确认原源版本仍可用。替盘、同路径更换目录或旧记录缺少身份证据时保留数据。同一卷与对象回到原路径后可再次恢复。[稳定卷与对象身份](../../crates/runtime/src/storage/identity.rs) · [事务恢复](../../crates/runtime/src/storage/transaction.rs)

实例创建在暂存目录生成 AVD 与清单，再改名发布并记录当前选择。删除实例只处理该实例私有存储。[实例注册与发布](../../crates/runtime/src/instances/mod.rs) · [AVD 生成](../../crates/runtime/src/instances/avd.rs)

目标布局把 Windroid 日志放在主数据目录，模拟器日志放在各自实例目录。两者分别按启动和日期留存，旧文件的兼容方式见[诊断日志](./诊断日志.md)。

## 五、安装契约

当前原生准备页逐项列出缺少的组件、版本、体积和许可。用户点击「同意并下载」启动传输，可在下载阶段暂停、继续，或在失败后重试。创建和启动实例以运行环境就绪为前提。组件缺失时，宿主快照仍提供已有实例、当前选择与可用操作。[宿主快照](../../crates/host/src/library.rs) · [命令准入](../../crates/host/src/library/commands.rs)

1. 同意许可后，在所选版本所在卷登记传输，按已有前缀申请续传。空间估算包括剩余压缩数据、完整展开副本及临时开销。
2. 下载和本地导入都核对官方档案长度与发布摘要。Android ZIP 使用 Google 发布的 SHA-1，scrcpy JAR 使用 SHA-256。
3. 核对完整展开清单中的相对路径、类型、执行位和 SHA-256，按版本原子发布。首次接入、同版本冲突判断、复制和修复均执行完整核验。日常自检可复用工作区内的核验缓存，界面区分快速自检与完整核验。
4. 损坏时展示具体资源、路径和原因。确认重新安装后，在目标卷准备与验证新副本，再切换版本。

安装暂存随资源保存在目标卷，多个工作区可接续同一包的下载。安装器按包标识和发布摘要定位暂存目录，读取其 `owner` 文件中的 `windroid-package-install-v1` 确认暂存格式。下载中断时，用户可从已有分片继续。若发布中断并留下 `publish.json`，需重新检查并确认恢复。安装器核对卷和目录身份，再核验已换入的版本或恢复原备份。身份不符时保留现场。

[准备状态](../../crates/runtime/src/provision/mod.rs) · [下载与续传](../../crates/runtime/src/provision/download.rs) · [解压与发布](../../crates/runtime/src/provision/archive.rs)

## 六、实例创建

### AVD 生成：手写 config.ini，不使用 avdmanager

**实测依据**：20 行手写配置即可启动成功，25 秒完成引导。`avdmanager` 需要额外 300 MB（JDK + cmdline-tools），且其输出是给开发者看的文本，解析脆弱。

```
选择模板 → 生成私有 AVD 索引与配置 → 保存实例清单 → 启动并检查设备就绪状态
```

**必须记录的键**：`hw.cpu.arch=arm64`。写成 `aarch64` 会导致模拟器 FATAL 退出。

### 设备模板

| 档位 | 分辨率 | dpi | 用途 |
|---|---|---|---|
| phone-1080 | 1080×2400 | 420 | 手机 |
| tablet-1200 | 1920×1200 | 240 | 平板 |
| tv-1080 | 1920×1080 | 320 | 电视 |
| tv-4k | 3840×2160 | 320 | 电视高配 |
| compact-720 | 1280×720 | 240 | 轻量/测试 |

模板是纯数据，可直接做单元测试（给定档位 + 镜像，断言产出的 `config.ini` 符合预期）。这比走 `avdmanager` 更可测。

### 创建与调整规格

新建表单及首次引导均按受管版本、所选镜像和模板计算单台上下限。保存时取得版本租约，重新核验元数据、整数范围及实例数据卷余量。镜像的 API、标签、ABI 和修订号仍保存于实例清单，CPU、内存、图形模式与最终分辨率保存在实例自己的 AVD。图形模式随实例传给 Emulator。[单台规则](../../crates/runtime/src/instances/specification.rs) · [AVD 发布](../../crates/runtime/src/instances/avd.rs)

实例规格从其私有 AVD 读取。已保存的内存低于镜像最低要求时，保留配置值，按预计实际分配量检查启动额度。停机编辑与启动共用实例运行锁，原子替换硬件键。若已有快照，变更后的启动跳过旧快照，直至同一配置完成新的快照保存。镜像绑定、分区和 Android 私有文件继续使用原件。[硬件编辑与最低分配](../../crates/runtime/src/instances/hardware.rs) · [快照回执](../../crates/runtime/src/instances/quick_boot.rs)

正常停止时先核对所连 AVD 的身份，向已挂载的客户机 `/data` 请求刷盘，再让 Emulator 保存 Quick Boot 快照。确认刷盘后，以停止时的快照签名登记可跳过的凭证。空闲冻结另需确认本轮快照已更新。运行中冷重启如无法确认刷盘，原进程继续运行。普通停止仍能回收未连上的进程，未获凭证的快照可正常恢复。跳过缺少刷盘凭证的快照前，须先正常恢复并停止一次。若该快照无法恢复，应用保留它和私有分区，需用备份恢复或另行修复客户机。[停机与身份核对](../../crates/runtime/src/instances/process.rs) · [快照与刷盘凭证](../../crates/runtime/src/instances/quick_boot.rs)

### 回读规则

工作台挂载每个实例时从 `instance.json` 读取模板、镜像和创建时的用户空间字节数，从该实例私有 AVD 的 `config.ini` 读取配置的 CPU 核数、内存 MiB 和主屏宽高。工作区重开时按原修订解析，其他修订可在相邻目录共存。缺失、无效或重复的硬件项在快照中为 `null`，其余字段仍可浏览。[规格读取](../../crates/runtime/src/instances/hardware.rs) · [宿主快照](../../crates/host/src/library.rs)

实例就绪后，运行时核实所持进程与 Android 设备身份，从该实例的 `hardware-qemu.ini` 回读模拟器本次生成的 vCPU 与内存参数。启动前的旧文件不能作为本次分配的依据，确认前和停止后均显示未知。该内存值表示模拟器交给客户机的容量，宿主进程常驻内存和 Android 内核可用内存各有独立口径。[就绪观测](../../crates/runtime/src/lib.rs) · [启动前后配置回归测试](../../crates/runtime/tests/instances.rs)

## 七、实例存储

### 能力表（全部实测确认）

| 操作 | API < 33 | API ≥ 33 |
|---|---|---|
| 创建时指定 ≥ 6 GiB | 可用 | 可用 |
| 创建时指定 < 6 GiB | 被抬到 6 GiB（API ≥ 24 时） | 同左 |
| 创建后放大 | 生效但**清空数据** | **完全无效** |
| 创建后缩小 | 不支持 | 不支持 |
| 写满后自动扩容 | 不会 | 不会 |

### 根因（源码依据）

文件 `platform/external/qemu/android-qemu2-glue/main.cpp`：

```cpp
// studio avd manager does not allow user to change partition size, set a
// lower limit to 6GB.
constexpr auto kMinPlaystoreImageSize = 6LL * 1024 * 1024 * 1024;
const int myApiLevel = avd ? avdInfo_getApiLevel(avd) : 1000;
if (myApiLevel >= 24 || fc::isEnabled(fc::PlayStoreImage)) {
    if (firstTimeSetup && hw->disk_dataPartition_size < kMinPlaystoreImageSize) {
        hw->disk_dataPartition_size = kMinPlaystoreImageSize;
        // Write it to config.ini as well, or we get all sorts of problems.
        avdInfo_replaceDataPartitionSizeInConfigIni(..., kMinPlaystoreImageSize);
    }
}
```

- 6 × 1024³ = 6442450944，与实测被写入的十进制值完全一致。
- API 24 是精确阈值（API 23 不触发、24 触发），跨模拟器版本稳定（33.1.24 / 35.2.10 / 37.2.13 行为一致）。
- API 33+ 无法放大的原因：该版本 userdata 使用 qcow2，而 resize 逻辑要求 `pathIsExt4`，条件不成立，整段逻辑被跳过。

### 用户空间在创建时确定

用户在创建时选择分区容量。表中验证的镜像在创建后扩大容量时，会重建用户数据或保留原容量，因此现有实例将此项作为只读规格。

注册表按实例所在卷的可用字节数取 70%，再向下取整为 GiB。上限达 8 GiB 时默认 8 GiB，只有 6–7 GiB 时默认 6 GiB，再低时提示释放空间。创建后保留原分区容量。[应用库创建命令](../../crates/host/src/library/commands.rs) · [空间检查](../../crates/runtime/src/instances/mod.rs)

## 八、端口分配

```
adb 是单 server 多设备模型（实测：只有一个进程监听 5037）
每个实例占 console 端口 + 其 +1（给 adb）
可用区间：5554–5584 的偶数，共 16 组
任一端口被占用 → 模拟器启动失败（官方文档确认）
```

分配器从 5554 步进 2，检查本机监听和已注册实例占用的端口对，成功后保存到实例清单。端口对用尽或启动时被外部进程占用会返回错误。显示会话的 adb forward 端口另外动态分配。

### 启动预留

普通启动和冻结恢复按将要分配的核数与客户机 MiB 申请同一份额度。所有活动预留之和最多为本机逻辑核数和物理内存的 50%。另以宿主实时内存压力和可新增量检查本次请求。警告压力下仍须满足两项内存检查，严重压力直接拒绝。过期或缺失的观测再读一次，仍无有效值时提示重试。端口按实际占用检查。[并发申请与重试](../../crates/runtime/src/admission/mod.rs) · [内核采样](../../crates/runtime/src/admission/observation.rs)

同一登录用户下的多个工作区和宿主进程，通过文件锁串行检查和登记活动预留。每笔预留记录自己的核数、内存及采样时刻，补扣同一有效观测之后的新申请。QEMU 继承预留文件描述符，停止过程中仍占用额度，进程退出后可回收。重新启动先按替换本实例检查，通过后停止旧会话，再以当下余量和所选资源根做完整启动检查。[进程与预留的生命周期](../../crates/runtime/src/instances/process.rs)

### 外部 adb 占用 5037

启动时用所选 Platform-Tools 的 `adb version` 确认协议。端口空闲时才允许该工具建立服务。设备枚举、shell、APK 传输、标签查询和每个 scrcpy 启动或清理命令，在创建客户端进程前都向实际本机端口发送只读 `host:version`。若会话运行期间服务改版或退出，该命令返回错误。工具和版本读锁随实例及窗口会话保留。[服务握手](../../crates/adb/src/service.rs) · [流会话命令](../../crates/stream/src/server.rs)

Emulator 使用私有 AVD、镜像修订目录和可写数据盘，子进程清除 `ANDROID_HOME` 与 `ANDROID_SDK_ROOT`，PATH 只含 macOS 系统命令目录。Windroid 使用显式路径启动受管 adb 服务供模拟器注册。Windroid 的协议检查覆盖自身发起的 adb 客户端；原生模拟器内部的服务通信由模拟器实现。服务在预检结束和客户端随后连接之间仍可能改变。[实例启动](../../crates/runtime/src/instances/process.rs)

每轮启动给 Emulator 分配新的私有临时目录。37.2.13 通过其中的 `netsim.ini` 找到本轮无线模拟服务，服务的 gRPC、HCI、TCP 和 WebSocket 端口由系统动态分配。因此停止先启动的实例时，其他实例仍持有自己的无线服务。正常退出后回收本轮目录，异常遗留的发现文件不会用于后续启动。[启动与回收](../../crates/runtime/src/instances/process.rs) · [双实例启停实测](../实测/07-全部实例批量启停.md)

## 九、失败分类

| 类别 | 处理方式 |
|---|---|
| 环境缺失（无运行时/镜像） | 引导安装，不计为错误 |
| 版本不满足（模拟器低于镜像要求） | 标记该镜像不可用，说明原因 |
| 端口耗尽 | 拒绝创建并报告端口范围 |
| 磁盘不足 | 创建前检查实际可用空间，数据盘超出上限时报告原因 |
| 网络失败 | 准备页报告失败原因，允许重试 |
| 启动超时 | 区分「慢」与「卡死」，保留日志路径 |

**adb 输出永远不是成功证据**，必须回读验证。

## 十、验收标准

在 Apple 芯片的 Mac 上以空的 `WINDROID_HOME`、默认组件来源打开应用包。从准备页同意许可并下载，创建实例并启动，确认能在设备窗口看到真实首帧。记录使用的组件版本和实例 serial，可据此复验。
