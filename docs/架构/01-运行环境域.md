# 运行时组件设计

## 本文档边界

本文覆盖 Windroid「运行环境域」的设计规格：运行时组件分级与版本策略、镜像源抽象、目录布局与安装契约、实例创建与 AVD 生成、实例存储能力、端口分配、失败分类与验收标准。

不覆盖：窗口/视频/输入链路（属流域与呈现域）、应用语义与设备能力（属设备域）、界面视觉规范。本文只描述契约与约束，不含实现进度。

支撑本文结论的实测证据见 [实测/01-运行环境域](../实测/01-运行环境域.md)。上一级文档见 [架构总览](../架构总览.md)。

标注约定：**实测** = 本机验证过；**源码依据** = 来自上游源码；**推断** = 未验证的判断，需后续确认。

## 一、运行环境域的定位

**职责**：让「启动一个 Android 实例」从零开始可用。管理运行时组件、系统镜像、实例存储、端口分配、进程启停。

**不负责**：窗口/视频/输入（属流域与呈现域）、应用语义（属设备域）。

**核心约束**：在零运行时、零镜像的状态下，界面必须完全可达；所有下载由显式引导触发，不做静默下载。

## 二、组件三级分级

| 级别 | 组件 | 大小 | 用户可见性 | 版本策略 |
|---|---|---|---|---|
| 一级 · 底层运行时 | emulator | 1.2 GB | 不可见、不可选 | 与 app 主版本绑定，同批升级 |
| 一级 · 底层运行时 | platform-tools (adb) | 37 MB | 不可见、不可选 | 同上 |
| 二级 · 协议绑定 | scrcpy-server | 733 KB | 不可见、不可选 | 跟 app 版本走；协议不兼容则拒绝连接 |
| 三级 · 系统镜像 | system image | 约 3.1 GB | **用户可选**，多版本共存 | 用户按「安卓版本」选择 |

### 版本耦合

**实测**：镜像的 `source.properties` 声明 `Pkg.Dependencies=emulator#X.Y.Z`，这是**最低版本要求**而非精确匹配——本机 emulator 37.2.13 运行声明要求 34.2.16 的镜像正常。

启动前校验，不满足则该镜像标记为不可用并说明原因。

**不安装多个 emulator 版本**：一份 emulator 1.2 GB 且测试矩阵翻倍，不值得。数据模型预留「镜像可绑定特定运行时」字段，但策略上不铺路。

## 三、镜像源抽象

```
ImageSource（接口）
├── GoogleOfficialSource    内置、默认
├── TencentCloudSource      内置、可选
└── UserDefinedSource       用户添加（元数据地址 + 包基址）
```

统一产出 `ImageDescriptor`：

| 字段 | 说明 |
|---|---|
| id | 唯一标识 |
| apiLevel | 安卓 API 级别 |
| tag | 镜像标签（如 google_apis / default） |
| abi | 架构（arm64 等） |
| revision | 镜像修订号 |
| requiresEmulatorMin | 来自 Pkg.Dependencies 的最低 emulator 版本 |
| sizeBytes | 解压后与下载体积 |
| files | `{url, sha1, size}` 三元组列表 |
| layout | 目录布局策略标识 |

### 两条必须遵守的规则

1. **元数据地址与包基址分开配置**。实测依据：腾讯云镜像的 repository XML 与 sys-img XML 都可用（HTTP 200，432 KB），但 3 GB 大包下载会超时（HTTP 524 / HTTP2 INTERNAL_ERROR），小包正常（1 MB/s）。两者必须能分别配置。
2. **失败不静默回退**。报明确错误 + 提供「切换到官方源重试」按钮，由用户点击。自动回退会让用户误以为国内源可用，实际一直在用国外源，反而掩盖问题。

### 布局适配

AVD 对镜像的唯一要求是「一个包含 `system.img` / `vendor.img` / `kernel-ranchu` / `ramdisk.img` 的目录」，通过 `config.ini` 的 `image.sysdir.1` 指向它。镜像目录的内部布局是**本项目的契约，不是 Google 的**——换成 AOSP 或 LineageOS 构建产物时，AVD 生成逻辑无需改动。

- 现在只实现 `StandardSDKLayout`（原样解压）。
- `CustomLayout` 只留字段不实现，等真正接入 AOSP/LineageOS 时再加。

### 镜像源实况（实测）

| 源 | repository XML | sys-img XML | 大包体下载 |
|---|---|---|---|
| Google 官方 | 可用 | 可用 | 7.9 MB/s |
| 腾讯云 | 200（432 KB） | 200 | 大文件 524 超时；小包 1 MB/s |
| 清华 TUNA | 404（仅提供 AOSP 源码，无 SDK 包） | — | — |
| 中科大 USTC | 404 | — | — |

## 四、目录布局

```
~/.windroid/
├── runtime/
│   ├── emulator/<version>/
│   ├── platform-tools/
│   └── scrcpy-server/<version>/
├── images/
│   └── <apiLevel>/<tag>/<abi>/
├── instances/
│   └── <uuid>/
│       ├── config.ini
│       ├── userdata-qemu.img
│       └── userdata-qemu.img.qcow2
├── staging/          下载中；未完成的一律在此
├── cache/            图标、元数据
└── logs/
```

**两条硬规则**：

1. 从 `staging/` 到目标目录是**原子改名**。没有完成标记的内容一律视为未安装并清理，不会被误判为已安装。
2. 版本目录带版本号（如 `emulator/37.2.13/`），升级时新旧并存，回退只需改指针。

## 五、安装契约

```
下载 → staging/ → 校验（sha1 + size）→ 原子改名 → 写完成标记
```

- 支持断点续传（HTTP Range）。
- 代理设置可选（跟随系统 / 手动指定）。
- 校验失败即删除，不留半成品。

### 下载引导流程

零状态可用性的具体体现：

```
首次启动
  ├─ 进入界面（无需任何下载）
  ├─ 顶部提示「需要准备运行环境才能启动实例」[开始准备]
  ├─ 点击 → 进度页（分项：运行时 / 镜像）
  │    · 每项显示：名称、大小、当前速度、剩余时间
  │    · 可暂停、可取消、失败可重试
  └─ 完成后 → 主界面解锁「创建实例」
```

不做静默下载：约 4.5 GB 是不可忽略的流量。

## 六、实例创建

### AVD 生成：手写 config.ini，不使用 avdmanager

**实测依据**：20 行手写配置即可启动成功，25 秒完成引导。`avdmanager` 需要额外 300 MB（JDK + cmdline-tools），且其输出是给开发者看的文本，解析脆弱。

```
模板（5 档）→ 写 <uuid>.ini + <uuid>.avd/config.ini → 启动 → 回读真实参数 → 存为实例元数据
```

**必须记录的键**：`hw.cpu.arch=arm64`。写成 `aarch64` 会导致模拟器 FATAL 退出。

### 模板库（5 档，自建，不抄 Pixel 参数集）

| 档位 | 分辨率 | dpi | 用途 |
|---|---|---|---|
| phone-1080 | 1080×2400 | 420 | 手机 |
| tablet-1200 | 1920×1200 | 240 | 平板 |
| tv-1080 | 1920×1080 | 320 | 电视 |
| tv-4k | 3840×2160 | 320 | 电视高配 |
| compact-720 | 1280×720 | 240 | 轻量/测试 |

模板是纯数据，可直接做单元测试（给定档位 + 镜像，断言产出的 `config.ini` 符合预期）。这比走 `avdmanager` 更可测。

### 回读规则

适用范围：所有可能被模拟器改写的参数。模拟器会在启动时静默改写配置并回写 `config.ini`——**实测**：内存 1536 MB 被抬到 2560 MB；分区大小 1G 被抬到 6 GiB。**界面显示一律使用回读值，不使用写入值。**

## 七、实例存储

### 能力表（全部实测确认）

| 操作 | API < 33 | API ≥ 33 |
|---|---|---|
| 创建时指定 ≥ 6 GiB | 可用 | 可用 |
| 创建时指定 < 6 GiB | 被抬到 6 GiB（API ≥ 24 时） | 同左 |
| 创建后放大 | 生效但**清空数据** | **完全无效** |
| 创建后缩小 | 不支持 | 不支持 |
| 写满后自动扩容 | 不会 | 不会 |

### 根因（源码依据）

文件 `platform/external/qemu/android-qemu2-glue/main.cpp`：

```cpp
// studio avd manager does not allow user to change partition size, set a
// lower limit to 6GB.
constexpr auto kMinPlaystoreImageSize = 6LL * 1024 * 1024 * 1024;
const int myApiLevel = avd ? avdInfo_getApiLevel(avd) : 1000;
if (myApiLevel >= 24 || fc::isEnabled(fc::PlayStoreImage)) {
    if (firstTimeSetup && hw->disk_dataPartition_size < kMinPlaystoreImageSize) {
        hw->disk_dataPartition_size = kMinPlaystoreImageSize;
        // Write it to config.ini as well, or we get all sorts of problems.
        avdInfo_replaceDataPartitionSizeInConfigIni(..., kMinPlaystoreImageSize);
    }
}
```

- 6 × 1024³ = 6442450944，与实测被写入的十进制值完全一致。
- API 24 是精确阈值（API 23 不触发、24 触发），跨模拟器版本稳定（33.1.24 / 35.2.10 / 37.2.13 行为一致）。
- API 33+ 无法放大的原因：该版本 userdata 使用 qcow2，而 resize 逻辑要求 `pathIsExt4`，条件不成立，整段逻辑被跳过。

### 产品决定：不提供「改分区大小」功能

- API 33+ 上它根本不工作，提供即欺骗。
- API < 33 上它清空数据，与用户预期（「只想装更多应用」）完全相反。
- 真正的需求是「装不下应用了」，正确回应是创建时给够。

创建时一次定死，档位为 6 / 8 / 16 / 32 GB + 自定义。下限 6 GiB，上限为可用空间 × 70%，并按 1024 单位取整、按数量级封顶。界面明确标注「创建后不可更改」。

## 八、端口分配

```
adb 是单 server 多设备模型（实测：只有一个进程监听 5037）
每个实例占 console 端口 + 其 +1（给 adb）
可用区间：5554–5584 的偶数，共 16 组
任一端口被占用 → 模拟器启动失败（官方文档确认）
```

分配器从 5554 步进 2，跳过被占用的成对端口。达到 16 个时拒绝创建，提示「已达并发实例上限」并提供「停止空闲实例」入口。

### 外部 adb 占用 5037

检测到非本应用启动的 adb server 时，提示「检测到其他 adb 服务占用端口，可能影响设备识别」，并提供「改用自带 adb」选项（adb 支持 `-P` 指定非默认端口）。不自动抢占。

## 九、失败分类

| 类别 | 处理方式 |
|---|---|
| 环境缺失（无运行时/镜像） | 引导安装，不计为错误 |
| 版本不满足（模拟器低于镜像要求） | 标记该镜像不可用，说明原因 |
| 端口耗尽 | 拒绝创建，给出替代动作 |
| 磁盘不足 | 创建前按「需求 × 1.2」校验（模拟器源码即用 1.2 系数） |
| 网络失败 | 明确报错 + 可选切换源，不静默回退 |
| 启动超时 | 区分「慢」与「卡死」，保留日志路径 |

**adb 输出永远不是成功证据**，必须回读验证。

## 十、验收标准

> 移走系统 SDK（或使用隔离的 HOME），仍能得到真实画面。

这是证明「自包含」的唯一方式。
